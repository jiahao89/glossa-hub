## 1. 项目背景与核心业务痛点

迈金（Magene）作为全球知名的智能骑行生态与硬件研发企业，旗下拥有智能 GPS 骑行码表、心率带、功率计、室内骑行台及配套跨平台 App。码表内置固件系统要求面向全球 50+ 个国家和地区销售，出厂标配内置支持 **16+ 种国际主流语言包**。

在引入专业化平台前，词条翻译与版本管理面临以下典型痛点：
1. **表格离线流转易损坏与行错位**：依靠飞书多维表格或 Excel 文件邮件传输，多人编辑时极易发生行错位、键名拼写错误、格式损坏或版本覆盖。
2. **多语言翻译周期长且成本高**：硬件新版本动辄增删数百条 UI 提示语与数据项，多国语言翻译严重依赖人工跟进，缺少上下文协同与统一术语指引。
3. **固件版本迭代缺乏可追溯性（Diff 困难）**：固件版本按硬件型号和批次迭代，旧版无法直观比对新增（ADD）、删除（DEL）与变更（MOD），一旦发生线上文字截断或翻译疏漏，难以追踪“谁在何地何时引入了改动”。
4. **专业术语打架与品牌风格失真**：骑行与功率计等专业名词（如“踏频”、“功率”、“累计爬升”、“平顺度”等）在不同语种下容易出现名词不统一，损害品牌专业度。
5. **多端发布缺乏工程化衔接**：翻译成果导出格式繁琐，研发需人工拷贝至嵌入式 C 数组或字符串表中，流程断层严重。

**GlossaHub 建设目标**：建设一个完全自主可控、私有化部署、面向大屏端的高性能 Web 词条协同与翻译管理平台，打通“项目管理 -> 词条录入 -> 智能键名生成 -> 术语库拦截 -> AI/人工翻译 -> 内容审核流 -> 差分比对 -> Git 风格版本追溯与时光机回退 -> 工业级多格式导出”全生命周期。

## 2. 总体架构与系统设计

### 2.1 技术栈选型
*   **前端应用**：React 18/19 SPA + Vite + Tailwind CSS + Lucide Icons，采用 `React.lazy()` 路由级按需加载与统一设计规范。
*   **后端服务**：Node.js / Express 模块化微单体架构（`server/app.cjs`），统一路由分发、中间件拦截、API 限流与错误处理。
*   **双数据库混合引擎**：
    *   **开发/单机环境**：本地嵌入式 SQLite (`glossahub.db`)，开启 WAL 模式、`synchronous = NORMAL`、`busy_timeout = 5000` 保障并发读写。
    *   **生产/云端环境**：PostgreSQL (Supabase)，通过统一数据抽象层 (`server/config/db.cjs`) 提供参数化查询适配、JSON 字段标准化与事务安全。
*   **部署架构**：
    *   前端托管于 **Vercel**（静态资源极速分发，`/api/*` 通过边缘轻量代理网关转发）。
    *   后端常驻托管于 **Render** / 云主机（常驻 Node.js 服务，统一管理数据库连接池、JWT 秘钥与翻译代理）。

### 2.2 核心安全与鉴权机制
1.  **分层 RBAC 权限控制**：
    *   **系统级角色 (`users.role`)**：
        *   `admin`（系统超级管理员）：拥有全站所有最高权限，可管理所有用户、重置密码、审计全库日志、系统危险维护清理，且在所有项目中自动穿透获得 `owner` 权限。
        *   `user`（普通用户）：需加入具体项目后根据项目角色执行操作。
    *   **项目级角色 (`project_members.role`)**：
        *   `owner`（项目拥有者）：拥有项目设置、Dify AI 引擎配置、成员权限分配、版本表新建/删除/克隆、语种增删改及回收站管理权限。
        *   `editor`（翻译编辑者）：可创建/修改词条、执行单行及批量 AI 翻译、KW 键名生成、CSV 导入等写操作。
        *   `viewer`（只读审核员）：仅可检索、查阅、比对数据及发起审核意见，严格禁止任何篡改或破坏性操作。
2.  **安全防护加固**：
    *   全 API 挂载 JWT 认证令牌，前端 401 自动失效清理。
    *   密码采用 `bcrypt` 慢哈希加盐存储，禁止明文流转；提供防暴力破解登录限流 (`loginLimiter`) 与高频写操作限流 (`writeLimiter`)。
    *   后端作为安全代理隔离 Dify API Key 与外部模型鉴权，防范 API 秘钥前端泄露与 SSRF 风险。

## 3. 功能模块详细需求与业务规范

### 3.1 仪表盘看板 (Dashboard)
*   **全局核心 KPI 指标**：
    *   当前项目版本大表总数、中文词条总键数（KW 数）、全语种完全翻译词条数、全站综合翻译就绪率。
*   **双重视图切换 (Tabs)**：
    *   **翻译覆盖率视图**：展示各语种词条填充完成率。
    *   **审核覆盖率视图**：统计进入 `APPROVED` / `PUBLISHED` 状态的优质词条占比。
*   **AI 翻译用量与成本监控 (AI Telemetry)**：
    *   今日消耗 Token 总量、今日调用次数、本周累计 Token 消耗。
    *   近 7 天每日 AI 调用消耗 Token 趋势折线图，提供成本与预算管控决策依据。
*   **多语种就绪进度条矩阵 (Target Language Progress Matrix)**：
    *   横向柱状图排布统计 16 种目标语种就绪率，依据阈值智能三色动态渲染：
        *   **绿色 (Green)**：覆盖率 $\ge 80\%$；
        *   **黄色 (Yellow)**：$30\% \le$ 覆盖率 $< 80\%$；
        *   **红色 (Red)**：覆盖率 $< 30\%$。
*   **实时动态轨迹 (CST 东八区)**：
    *   展示最近操作动态，包含操作人、所属数据表、KW 及变动动作。当天修改仅显示时分秒，历史修改展示完整年月日。
    *   支持点击“查看详情”无缝携带参数直接跳转至词条大表定位对应版本。

### 3.2 词条协同网格 (Translation Manager)
*   **高密度多语种响应式网格**：
    *   固定前置列：操作栏（锁定/解锁/删除/审核）、审核状态徽标、来源标识、KW 唯一键名、中文原文 (`zh_cn`)、所在页面、字号类别。
    *   横向动态扩展列：平铺渲染当前项目启用的 16+ 种国际语言（英语、德语、法语、西班牙语、意大利语、日语、韩语、俄语、葡萄牙语等）。
*   **单元格行内编辑与高亮跟踪**：
    *   双击任意单元格直接唤起编辑，提供清晰焦点边框。
    *   **脏数据状态跟踪**：修改但未提交的单元格呈现琥珀黄高亮，新增未提交行呈现清新绿高亮。
    *   **防抖与自动保存**：前端具备 1.5 秒 Debounce 自动保存机制，并辅以本地 `localStorage` 脏数据防意外刷新丢失机制。
*   **乐观锁并发控制 (Optimistic Locking)**：
    *   更新请求强校验 `updated_at` 时间戳。若两人同时编辑同一词条，后提交者收到 `409 Conflict` 冲突提示，防止互相踩踏冲刷数据。
*   **词条行级保护锁 (`is_locked`)**：
    *   已被管理员或负责人加锁的词条，行内输入禁止修改，批量清理或同步跳过该词条，防止基线词条被误篡改。
*   **翻译内容审核状态机 (Review Workflow)**：
    *   词条支持 5 种生命周期状态：
        1. `DRAFT`（草稿）：初始录入或机翻未校验状态；
        2. `PENDING_REVIEW`（待审核）：翻译完成，等待语言负责人审核；
        3. `APPROVED`（已审核）：语言专家或质检通过；
        4. `PUBLISHED`（已发布）：固件封板发布就绪；
        5. `REJECTED`（已驳回）：审核不通过，记录 `reject_reason`（驳回原因），高亮警示提示修改。
*   **丰富批量操作工具箱**：
    *   **批量翻译**：指定目标语种范围，支持“翻译所有未翻译项”或“翻译当前选中项”。
    *   **批量生成 KW 键名**：针对无键名或临时键名的词条，一键批量分析中文含义并规范化生成标准 `KW_` 键名。
    *   **批量审核与流转**：一键批量置为已审核、待审核或批量驳回。
    *   **批量清空/删除**：提供二次确认与写操作限流保护。
    *   **跨表复制/内容转移**：支持选定词条批量复制迁移到其他固件版本表。
    *   **清理空词条 (Clean-empty)**：自动剔除既无键名又无中文内容的冗余废弃行。

### 3.3 翻译引擎与 Dify 智能工作流 (AI Translation Engine)
*   **双层术语拦截漏斗机制 (Two-tier Intercept Funnel)**：
    1.  **第一层·全词精确匹配 (Full Match Bypass)**：翻译前优先比对项目专业词汇库，命中全词直接以本地术语库作为终态，标记为 `tm` 来源，跳过大模型调用，实现毫秒级响应并节省 Token 消耗。
    2.  **第二层·局部模糊匹配注入 (Partial Match Prompting)**：若未命中全词，提取词条中涉及的骑行与固件术语规则，作为 `glossary_context` 动态拼装注入大模型 Prompt，强制 AI 遵守既定名词标准。
*   **智能翻译来源追踪 (Provenance Tracking)**：
    *   数据结构通过 `translations_meta` 字典字段持久化追踪各语种翻译产生途径：
        *   `ai`（AI 自动翻译生成）：单元格左上角浮现 Bot 机器人图标；
        *   `tm`（术语库/翻译记忆库直通）：单元格左上角浮现绿色对勾图标；
        *   `human`（人工直接录入/手工润色）：无图标，保持纯净文本。
*   **高可用模型故障自愈与多 Key 容灾 (Failover)**：
    *   后端实现 `executeDifyWithFailover` 机制，依次轮询“项目自定义 Dify 配置 -> 企业私有网关 -> 官方公有网关”，并在单个 Key 失效或超额时自动剔除轮转下一个候选 Key。
*   **标准 KW 键名生成规则**：
    *   整合固件骑行高频词典 (`FIRMWARE_UI_DICT`) + Dify 工作流 + 备用翻译引擎。
    *   输出自动清洗为全大写蛇形命名，自动补齐 `KW_` 前缀，例如：`骑行结束` $\rightarrow$ `KW_STOP_RIDE`。

### 3.4 动态自适应专业词汇库 (Glossary Dynamic Engine)
*   **多列动态 CSV 解析与导入**：
    *   系统摒弃传统固定列约束，支持导入任意列数、任意列名的高维术语 CSV。
    *   精准提取 `CN`、`EN`、`DE` 等多国语言对照列及 `Component`、`Context` 等工程列，全字段无损持久化。
*   **表头自适应 Th 渲染**：
    *   词汇库前端表头严格依据导入文件的 `headers` 动态生成，缺失自定义表头时优雅降级为“中文术语、英文对应、说明定义”三列默认视图。
*   **术语容量与检索**：
    *   常态化实时展示当前词库收录词条总数（`共包含词条：X 条`），提供高频词汇毫秒级实时搜索。
*   **高保真无损 CSV 导出**：
    *   导出时自动遵循原本列顺序与内容结构，支持译员线下润色后二次增量无缝导入。

### 3.5 固件版本差分比对 (Comparison Engine)
*   **跨版本智能审计对比**：
    *   支持在任意两个固件数据表之间发起比对（“对比源版本 A” vs “基准版本 B”）。
*   **三维语义差异分析**：
    *   **新增 (ADD)**：A 表独有而在 B 表不存在的词条，以清新绿色标识。
    *   **删除 (DEL)**：B 表独有而在 A 表已移除的词条，以醒目红色标识。
    *   **修改 (MOD)**：两表均有但翻译文本不一致的词条，以暖黄色标识，并展示新旧译文双列直观 Diff。
*   **假差异智能清洗消除 (False Diff Normalization)**：
    *   自动识别并过滤无实质意义的符号差异：英文半角引号 vs 中文全角弯引号、连续空格、全角空格、Unicode 省略号（`…` vs `...`）等，确保译员聚焦真正的内容变更。
*   **一键差分同步 (Apply Diff)**：
    *   支持选择将比对出的新增与修改词条，一键增量合入目标版本表，大幅降低版本迭代时的迁移成本。

### 3.6 版本管理与数据克隆 (Versions Manager)
*   **版本大表全景一览**：
    *   列表化展现固件版本表名、词条总量、就绪进度、创建时间、最近更新时间及创建人。
*   **重命名与元数据编辑**：
    *   支持弹窗即时重命名表名，自动同步更新所有关联日志与视图。
*   **一键数据深度克隆 (Deep Clone)**：
    *   新固件立项时，支持一键完整克隆基准版本的全部词条内容、KW 键名、16 种语种翻译值及 `translations_meta` 来源属性，建立独立版本基线。
*   **分块大批量继承机制 (Inherit Chunk)**：
    *   提供批量继承向导，针对上千条超大版本表，后端通过分页分块事务（Chunk Size 100~200）稳定搬迁，避免大事务锁表或云端超时。

### 3.7 语种字典配置 (Languages Manager)
*   **自定义目标语种池**：
    *   支持为项目自由增删目标语种，定义语言代号（如 `EN`、`FR`、`JA`）、展示标签（如 `EN（英文）`）及网格中从左至右的排列次序。
*   **多别名兼容与历史映射**：
    *   内置 `LEGACY_TO_NEW_LANG_MAP` 字典，自动兼容老版本数据中的非规范语种代号（如 `English` $\rightarrow$ `EN（英文）`），保障历史导入文件无缝兼容。

### 3.8 操作审计日志与时光机回退 (Audit Logs & Rollback Engine)
*   **不可篡改审计追踪**：
    *   全量数据库日志记录每一次修改行为：操作人、东八区时间戳、版本表名、词条 KW、操作类型（新增/修改/AI翻译/批量审核/清理等）及变更详情。
*   **Git 风格可视化 Diff**：
    *   日志支持展开查看变动快照，红绿双色清晰标记被修改词条各字段的前后差异。
*   **时光机一键回退与“后悔药”快照机制**：
    *   词条的每一次更新都在统一数据库事务中生成不可变的 `term_snapshots` 快照。
    *   在日志列表或词条历史弹窗中，用户可挑选任意历史节点一键回滚该词条；**回退操作在执行前会自动为当前状态生成一份崭新快照（“后悔药”机制）**，保证回退动作本身具备可逆性。

### 3.9 数据安全回收站 (Recycle Bin)
*   **防误删软删除设计**：
    *   固件版本表、专业词库表、语种配置被删除时，系统不直接物理 DELETE，而是将关联数据实体与元数据序列化打包存入 `recycle_bin`。
*   **30 天生命周期管理**：
    *   记录删除操作人与自动过期时间戳（`expires_at`），默认保留 30 天，超期自动安全脱敏与物理清理。
*   **一键无损完整还原**：
    *   仅限管理员与项目 Owner 在回收站中发起还原，系统自动在独立事务内重建物业、级联还原所有被删词条。

### 3.10 工业级导入与导出 (Import & Export Pipeline)
*   **RFC-4180 标准 CSV 导入/导出**：
    *   严格遵循 RFC-4180 标准，完美处理单元格内换行、英文逗号与包含双引号的复杂文本。
    *   导出自动添加 UTF-8 BOM 标记（`\uFEFF`），彻底解决 Windows Excel 打开中文多语种出现的乱码问题；导出自动智能剥离内部工程辅助列，输出纯净多语言包。
*   **带视觉样式的专业 Excel (.xlsx) 导出**：
    *   采用 `ExcelJS` 引擎生成原生 Excel 文档，深色商务表头、居中对齐与细边框网格。
    *   **差异高亮持久化导出**：新增词条整行标绿、修改过的单元格标黄，方便固件外包审校团队一目了然。
*   **CSV 导入安全增量合并**：
    *   导入前自动校验表头合法性与键名唯一性，支持“仅新增”、“覆盖冲突”多种合并模式，并设防空词条安全拦截机制。

### 3.11 设计系统与通用组件规范 (Design System & GlossaModal)
*   **设计规范与沉浸式体验**：
    *   遵循 Tailwind 响应式布局与暗黑（Dark Mode，默认）/ 明亮（Light Mode）双主题色彩体系。
    *   页面加载前执行防闪烁脚本，无缝同步本地存储偏好。
*   **统一模态窗规范 `GlossaModal`**：
    *   统一将弹窗背景设为 8px 高斯模糊遮罩（`backdrop-filter: blur(8px)`）。
    *   **WAI-ARIA 无障碍标准**：强制挂载 `role="dialog"`、`aria-modal="true"` 及 `aria-labelledby`。
    *   **交互与生命周期规范**：支持键盘 **ESC** 键快速退出、点击遮罩外部退出（异步翻译或写操作期间支持 `closeDisabled` 锁定防护）、焦点自动捕捉捕获及展开期间 Body 滚动锁定。

## 4. 数据库实体与存储规范

系统统一管理以下核心实体表：
1.  **`users`**：系统用户表（id, username, password_hash, role, created_at）。
2.  **`projects`**：项目空间表（id, name, description, dify_config, created_at）。
3.  **`project_members`**：成员权限表（id, project_id, user_id, role, created_at）。
4.  **`versions`**：固件版本数据表（id, project_id, version_name, created_at, updated_at）。
5.  **`terms`**：核心词条实体表（id, version_id, kw, context, zh_cn, translations, translations_meta, is_locked, status, reject_reason, sort_order, created_at, updated_at, updated_by）。
6.  **`term_snapshots`**：词条快照时光机表（id, term_id, version_id, kw, context, zh_cn, translations, translations_meta, snapshot_reason, created_at, created_by）。
7.  **`glossary_tables`** 与 **`glossary_terms`**：专业术语库及条目表。
8.  **`languages`**：项目多语言字典定义表。
9.  **`ai_usage_logs`**：AI 翻译 Token 与耗时遥测日志表。
10. **`logs` / `logs_v2`**：全量系统与词条操作审计日志表。
11. **`recycle_bin`**：软删除安全回收站归档表。

## 5. 版本演化历史与路线图 (Roadmap)

*   **v0.1 (历史初期)**：基于飞书多维表格与低代码插件形态，验证词条录入与 AI 翻译的可行性。
